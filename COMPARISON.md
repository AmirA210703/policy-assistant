### Comparison and preferred approach

The three approaches were tested on the same 28 questions against the 98-policy database: direct, paraphrased, missing-detail, out-of-scope and ambiguous questions. Answers were generated with Gemini 3.5 Flash Lite and checked by a separate judge model, Gemini 3.1 Flash Lite. The rules-based search (BM25 with a synonym table) answers in about 1 ms with zero tokens, and because it returns policy text word for word it cannot invent facts. It picked the correct policy in 92.9% of cases, but it fails when the wording does not match the policy. "Can I work from home on Mondays and Fridays?" returned the Home Office Equipment Policy, and "Can I bring my dog to the office?" returned the Office Access Policy instead of saying the topic is not covered. It also cannot tell the user that a detail, such as the number of sick days, is missing. The LLM without a vector index receives the whole database in every prompt (about 2,170 tokens per question). It found the correct policy in 96.4% of cases and declined all five out-of-scope questions; its only miss was declining the ambiguous "Who pays for my certification course?". The LLM with a vector index sends only the four most similar policies (about 380 tokens, 5.7 times fewer) and found the correct policy in all 28 cases. Neither LLM gave an unsupported answer: on the six missing-detail questions both said explicitly that the detail is not in the policy. Median response times were 5.0 s without and 11.9 s with the vector index. The difference comes mainly from the extra embedding call per question and from the free Gemini API being overloaded during the test (several automatic retries), so the times reflect API load more than the methods themselves.

The preferred approach is the LLM with a vector index. It had the highest accuracy and the same zero rate of unsupported answers, while using almost six times fewer tokens per question. That saving grows with the database, because the full-context prompt gets longer with every policy added, while the retrieved context stays at four policies. Its slower response time is a property of the setup rather than the method: it could be reduced with a local embedding model or a paid API tier. The rules-based search remains useful as an instant, free fallback, but it cannot handle wording it has no rule for. The results come with three caveats. The test set is small. The synonym rules were written with the test questions in mind, so the rules-based score is optimistic. The zero unsupported rate reflects a prompt that explicitly tells the model to refuse rather than guess, and it is measured by an LLM judge, so it is an estimate rather than a guarantee.
